1. Cómo usar esta guía

Esta guía explica cómo está construido BUFINS por dentro: qué carpeta hace qué, por dónde pasa una petición, cómo se guarda un dato y por qué el código está escrito así. Está pensada para leerla con el proyecto abierto: cada explicación señala un archivo real y muchos fragmentos están copiados tal cual del código.

Si quieres entender el sitio
  • Lee las secciones 2 a 5 (mapa, carpetas, recorrido de una petición y capas).
  • Sigue con 6 a 9 (datos, dependencias, seguridad y cargue) cuando necesites saber cómo se protege o se guarda algo.
Si quieres aprender C# y .NET
  • Ve directo a la sección 14 (glosario con ejemplos del propio código) y a la 15 (ruta de lectura de archivos).
  • La sección 13 es una receta para practicar: agregar una pantalla nueva de principio a fin.

Fecha de esta guía: 2026-11-16. Describe el sitio después de la reingeniería posterior a la migración a .NET 10 (fases 0 a 9 de .claude/notas/refactor-plan.md). Si cambia la estructura, se actualiza aquí y en Tools/Documentacion/doc_arquitectura.py.

2. Mapa del sistema

BUFINS Customers es una aplicación ASP.NET Core MVC sobre .NET 10. MVC significa que el trabajo se reparte en tres piezas: Modelo (los datos), Vista (la pantalla HTML) y Controlador (quien recibe la petición y decide qué hacer).

Regla de oro de la arquitectura: el controlador es delgado y el servicio es el que sabe. Si te encuentras escribiendo una regla de negocio dentro de un controlador, probablemente va en un servicio.

4. El recorrido de una petición

Cuando alguien abre /Auditoria ocurre esto, en este orden. Entender este recorrido explica casi todo el comportamiento del sitio.

  1. Entrada. IIS entrega la petición a la aplicación .NET 10 (alojamiento in-process).
  2. Manejo de errores (UseExceptionHandler) y la red de seguridad que registra en el log cualquier excepción que llegue hasta ahí.
  3. Páginas de error de la marca para 403 y 404 (no se aplican a /api, que responde siempre JSON).
  4. Compresión Brotli/Gzip y el middleware CabecerasSeguridad, que agrega la política de seguridad de contenido (CSP) con un nonce distinto por petición.
  5. Archivos estáticos: lo que empieza por /Assets se sirve desde disco con caché de un año (las URL llevan ?v= para renovarla).
  6. Idioma: la cookie lang decide es-CO o en-US.
  7. Enrutamiento: /Auditoria se resuelve a AuditoriaController.Index con la ruta {controller}/{action}/{id?}. Si empieza por /api/v1 lo toma antes el middleware de la API.
  8. Filtros globales, en este orden: registro de errores, carga de empresas y escenarios para la vista, cambio de clave obligatorio, registro de navegación y manejo del token anti-falsificación.
  9. Filtros de la acción: [ValidarSesion] (¿hay usuario?) y [RequierePermiso("…")] (¿tiene el permiso?). Si fallan, devuelven login o 403 y la acción ni se ejecuta.
  10. El controlador ejecuta su método, llama a uno o varios servicios, y estos usan Bd para llamar a SQL Server.
  11. La respuesta: una vista Razor (HTML), un Json(...) o un archivo (Excel, PDF).

5. Las capas con un ejemplo real

El módulo más pequeño y completo es el de Escenarios. Sirve para ver las tres capas juntas.

Modelo: la forma de los datos

Servicio: lo que sabe el negocio y habla con la base de datos

Controlador: recibe, valida, llama y responde

Vista: lo que ve el usuario

El controlador termina con View("~/Views/Configuracion/GestorEscenarios.cshtml", escenarios). Una vista Razor es HTML con partes de C# que empiezan por @. Los textos nunca van escritos a mano: se leen del archivo de recursos con @Resources.Strings.Clave, de modo que existen en español e inglés.

Reglas de cada capa
  • Un controlador nuevo hereda de BaseController y lleva [ValidarSesion] si requiere usuario.
  • Un servicio nuevo hereda de BaseService, que ya trae CadenaConexion.
  • Los errores al navegador salen con MensajeError(ex), que registra el detalle y muestra un código de referencia.
  • Los textos van siempre en los dos archivos .resx.
Reglas que protegen los datos
  • Toda acción acotada por empresa usa EmpresaAccesoHelper, nunca una comparación directa de ids.
  • Toda acción que cambia datos se audita con RegistrarCambio.
  • Las consultas son siempre parametrizadas (nada de concatenar valores del usuario en el SQL).
  • El SQL debe funcionar en SQL Server 2012.

6. Acceso a datos

BUFINS usa ADO.NET directo con procedimientos almacenados en SQL Server; no usa un ORM como Entity Framework. Es más verboso pero predecible y muy rápido.

El ayudante Bd

Hasta la reingeniería, cada consulta repetía unas ocho líneas (abrir conexión, crear comando, agregar parámetros, ejecutar). Ahora Helpers/Bd.cs lo hace una vez:

Método de BdPara quéEjemplo de uso
EjecutarINSERT, UPDATE, DELETE o un procedimiento; devuelve las filas afectadas.Bd.Ejecutar(cadena, sql, new { Id = id })
Escalar<T>Un solo valor (un COUNT, un id nuevo…).Bd.Escalar<int>(cadena, "SELECT COUNT(*) FROM …")
Lista<T>Todas las filas convertidas a objetos.Bd.Lista(cadena, sql, r => new Escenario { … })
Leer y LeerPrimeraRecorrer las filas (o solo la primera) con tu propio código.Bd.Leer(cadena, sql, r => ids.Add(Convert.ToInt32(r["Id"])))
Primero<T>La primera fila convertida, o nulo.Bd.Primero(cadena, sql, parametros, r => …)

El acceso manual (SqlConnection + SqlCommand) se sigue usando donde Bd no llega: transacciones, parámetros OUTPUT, varios conjuntos de resultados y carga masiva (SqlBulkCopy).

Ideas que conviene recordar

  • Multiempresa: casi toda tabla de datos tiene IdEmpresa; el código nunca lee datos sin filtrarlo.
  • Escenarios: las tablas de datos cargados tienen IdEscenario (por defecto 1 = principal): una copia paralela de los datos por empresa. Las lecturas usan ISNULL(IdEscenario,1) = @IdEscenario.
  • Columnas nuevas incrementales: si una columna puede no existir todavía en algún entorno, se lee dentro de un try/catch (IndexOutOfRangeException) y el código sigue funcionando sin ella.
  • Scripts SQL manuales: los cambios de base de datos se aplican a mano en cada entorno; no se debe asumir que un script ya corrió.
  • Modelos de cálculo: los informes leen tablas ya calculadas (dbo.Modelo*); nunca ejecutan los procedimientos de cálculo en vivo.

7. Inyección de dependencias

Un controlador necesita servicios para trabajar. En vez de crearlos él mismo con new, los recibe al construirse: eso se llama inyección de dependencias.

  1. Al arrancar, Program.cs llama a AddServiciosBufins() (archivo Infra/ServiciosExtensions.cs).
  2. Esa función busca por reflexión todas las clases públicas que terminan en Service dentro de bufinscustomers.Services y las registra como transitorias (una instancia nueva cada vez que se piden).
  3. ASP.NET Core, al crear un controlador, mira los parámetros de su constructor y entrega cada servicio.
  4. La prueba InyeccionDependenciasTests revisa que todo parámetro de todo controlador sea resoluble; si agregas uno que no está registrado, falla en las pruebas y no en producción.

Los servicios, ayudantes y filtros estáticos siguen creando otros servicios con new. Convertirlos a inyección sería un cambio mucho mayor sin beneficio inmediato; el código nuevo en controladores sí usa el constructor.

9. El cargue de datos (Excel y API)

Es el corazón del sistema: los clientes suben su información contable y ese dato alimenta todos los informes. Por eso tiene las protecciones más estrictas.

Subir Excel
o enviar por API
Staging
se guarda aparte
Validación
reglas del procedimiento
Revisar
el usuario ve el impacto
Confirmar
una sola transacción
  • Dos pasos: subir solo escribe en tablas temporales Staging_Ini_* y valida. Nada real cambia hasta confirmar.
  • Todo en una transacción al confirmar: copia de seguridad (snapshot) → borrados → carga definitiva → auditoría. Si algo falla, no queda nada a medias.
  • Regla de oro: el cargue nunca puede dejar un año vacío; hay un umbral que bloquea reducciones fuertes.
  • Un lote activo por llave (empresa, año, modo y escenario) y ningún lote puede quedar «pegado» (abandono, recarga, fin de sesión, limpieza).
  • Historial: se conservan versiones comprimidas para deshacer, con un respaldo automático antes de restaurar.

Paridad Excel ↔ API: el cargue por Excel y el de la API deben tener las mismas validaciones. Por eso toda regla va en el orquestador o en el procedimiento sp_ValidarCargueStaging, que sirven a las dos entradas. Lo que es propio de cada entrada (sesión y token en el Excel; clave, IP y límites en la API) se cambia en las dos.

10. Informes, modelos e inteligencia artificial

Los informes (PYG, Balance, Tesorería, Flujos, Indicadores…) comparten la misma forma. Aprender uno es aprender todos.

  • Los informes no calculan en vivo: leen tablas materializadas (dbo.Modelo*) que llena la ejecución de modelos.
  • Un servicio por informe (InformePYGService, InformeBalanceService…) que devuelve un modelo de vista; el controlador solo valida acceso y lo entrega.
  • Elementos comunes: botón Exportar estándar (_ExportMenu), logo de la empresa, tema de colores, comentarios de gestión y documentación propia, siempre con las mismas piezas compartidas.
  • El correo de un informe se reconstruye en el servidor: nunca se confía en las cifras que manda el navegador.
  • IA: todo uso de inteligencia artificial pasa por IAGateway, que controla el acceso por empresa, mide el consumo y solo envía datos de las tablas Modelo*, nunca datos de detalle.

11. La interfaz: Razor, CSS y JavaScript

  • Razor (.cshtml): HTML con C#. Cada pantalla vive en Views/<Área>/; el marco común está en Views/Shared/_Layout.cshtml y las piezas reutilizables empiezan por guion bajo (_ExportMenu, _LoaderDots…).
  • Librerías: Bootstrap 4.6 con el tema SB Admin 2, jQuery 3, Chart.js, jsPDF y html2canvas (PDF e imagen), SweetAlert2 (diálogos), Select2 y Font Awesome (iconos).
  • Estilo único: bufins-components.css define botones, tarjetas, tablas y modales; antes de crear una clase nueva se busca una existente.
  • Idiomas: ningún texto va escrito en la vista; se usa @Resources.Strings.Clave. Para JavaScript, el texto se inyecta desde Razor a una variable.
  • CSP estricta: no se permiten manejadores en línea (onclick…). Se usan data-* y listeners; inline-handlers.js traduce llamadas simples. Los <script> reciben el nonce automáticamente.
  • Paquetes y versiones: los enlaces a CSS y JS propios usan AssetVersion.Url(...), que agrega ?v= con la fecha del archivo para que el navegador recargue al publicar.

13. Receta: agregar una pantalla nueva

Esta es la lista que se sigue para cualquier pantalla nueva. Sirve también como ejercicio para aprender cómo encajan las piezas.

  1. Textos: agrega las claves en Strings.resx y Strings.en-US.resx (mismo nombre en ambos), con el formato Area_Elemento.
  2. Modelo: crea la clase de datos en Models/ (solo propiedades).
  3. Servicio: crea MiCosaService : BaseService en Services/ y usa Bd.* para leer y escribir. Si hay procedimiento almacenado, el script SQL se aplica a mano en cada entorno.
  4. Controlador: hereda de BaseController, lleva [ValidarSesion] y [RequierePermiso("CODIGO")] y recibe sus servicios por constructor primario. El servicio se registra solo.
  5. Empresa: si los datos son de una empresa, verifica con EmpresaAccesoHelper o TieneAccesoEmpresa(id).
  6. Vista: crea la vista Razor en la carpeta de su área con el esqueleto estándar (cabecera, filtros, tabla) y las clases de bufins-components.css.
  7. Menú: agrega la opción en la tabla MenuOpciones para que aparezca en el menú lateral y en el gestor de permisos.
  8. Auditoría: si la acción cambia datos, llama a RegistrarCambio tras el éxito.
  9. Notificación: si la operación es larga o importante, crea una notificación interna con NotificacionesService.
  10. Documentación: si es una pantalla nueva, crea su documentación oficial y, si se quiere, agrégala a la biblioteca «Documentación BUFINS».
  11. Verificar: compila con --no-incremental, corre las pruebas y revisa la pantalla.

Si la pantalla es un informe, además lleva: la cápsula «Información modelo Bufins», el botón Exportar estándar, el logo de la empresa, el tema de colores y, si tiene cierre mensual, los comentarios de gestión.

14. Aprender C# y .NET con el propio código

Cada concepto va con un ejemplo real de BUFINS. Abre el archivo indicado y búscalo: verlo en su contexto es la mejor forma de aprenderlo.

Namespaces y usingC# / .NET

Un namespace agrupa clases con un nombre que no se repite. using te deja escribir el nombre corto. Aquí cada carpeta tiene su namespace (bufinscustomers.Services, bufinscustomers.Helpers…).

Clases y propiedadesC# / .NET

Una clase es una plantilla de objetos. Una propiedad ({ get; set; }) es un dato con su lectura y escritura. Los modelos son clases con solo propiedades.

HerenciaC# / .NET

Una clase puede heredar de otra y reutilizar lo suyo. Todos los controladores heredan de BaseController (que trae R(...), MensajeError, TieneAccesoEmpresa…) y todos los servicios de BaseService (que trae CadenaConexion).

Constructor primario (C# 12)C# / .NET

Los parámetros de la clase se escriben en su cabecera y están disponibles en todos sus métodos. Reemplaza el campo + constructor + asignación de siempre.

AtributosC# / .NET

Los corchetes colocan metadatos sobre una clase o método. Aquí controlan seguridad y comportamiento HTTP: el filtro se ejecuta antes de la acción.

Clases y métodos estáticosC# / .NET

Un miembro static pertenece a la clase y no a un objeto: se llama sin new. Los ayudantes del sitio son clases estáticas.

using como bloque y try/catchC# / .NET

Un objeto que usa recursos (una conexión) se envuelve en using: al terminar el bloque se cierra solo. try/catch atrapa los errores para decidir qué hacer.

GenéricosC# / .NET

El tipo entre < > es un parámetro: el mismo código sirve para varios tipos. Escalar<int> devuelve un entero; Escalar<string>, un texto.

Lambdas y delegadosC# / .NET

Una lambda (x => …) es una función corta que se pasa como dato. Bd.Leer recibe una función que ejecuta por cada fila.

LINQC# / .NET

Consultas sobre colecciones con métodos encadenados: Where (filtrar), Select (transformar), Any (¿alguno cumple?), ToList (materializar).

Parámetros outC# / .NET

Un método devuelve un valor y, además, deja otros en variables que le pasas con out. El patrón Try… devuelve true/false y el resultado por out.

Valores nulos: ?, ?? y ?.C# / .NET

int? es un entero que puede ser nulo. a ?? b usa b si a es nulo. x?.Prop evita el error si x es nulo. string? (con #nullable enable) declara que un texto puede ser nulo.

Objetos anónimosC# / .NET

Un objeto sin clase, con las propiedades que escribas. Se usa para parámetros SQL y para respuestas JSON rápidas.

Coincidencia de patronesC# / .NET

is comprueba el tipo y, si coincide, ya te entrega la variable tipada. switch elige según valores.

TuplasC# / .NET

Devolver varios valores con nombre sin crear una clase.

Métodos de extensiónC# / .NET

Agregan métodos a un tipo existente. El primer parámetro lleva this. Así builder.Services.AddServiciosBufins() parece un método de IServiceCollection.

Clases parcialesC# / .NET

partial permite repartir una misma clase en varios archivos. Aquí se usa para que ningún archivo sea enorme: DatosController.cs, .Cargue.cs, .Modelos.cs y .Hallazgos.cs son una sola clase.

Interpolación de textoC# / .NET

El $ antes de las comillas permite insertar valores dentro del texto entre llaves.

Constantes y enumeracionesC# / .NET

const es un valor fijo con nombre; evita escribir el mismo texto en muchos sitios y equivocarse.

async y awaitC# / .NET

Deuda conocida y decisiones

  • Mensajes de error: ningún error técnico llega al navegador con su texto original. Los controladores usan MensajeError(ex) y los servicios MensajeErrorHelper.Crear(...): registran el detalle y muestran un código de referencia (se busca en App_Data/logs). Se conservan a propósito el diagnóstico SMTP del correo de prueba y los diagnósticos del archivo de cargue del cliente.
  • Capa Compat (sesión, cookies, caché, configuración): se conserva a propósito; reemplazarla toca el inicio de sesión y requiere pruebas de integración antes.
  • JavaScript en las vistas de informes: unas 12.000 líneas en línea; el PDF y el slider de rango están copiados con variaciones. Unificarlos requiere probar en navegador informe por informe.
  • Nulabilidad: activada por archivo en 8 ayudantes; el resto del proyecto la tiene desactivada (activarla en todo da unos 2.000 avisos, sobre todo en los modelos).
  • async: el código es mayormente síncrono; convertirlo es un cambio en cascada con poco beneficio hoy.
  • Despliegue: la publicación la ejecuta el responsable con su usuario; la contraseña nunca se comparte por chat.

17. Preguntas frecuentes

¿Dónde empiezo si nunca he programado en C#?

En la ruta de lectura (sección 15), pasos 1 a 3, con el glosario (sección 14) al lado. Cada concepto del glosario tiene su ejemplo real.

¿Por qué no se usa Entity Framework?

El sitio nació con ADO.NET y procedimientos almacenados, y el cálculo financiero vive en la base de datos. Cambiarlo sería reescribir todo el acceso a datos; en su lugar se redujo la repetición con Bd.

¿Por qué hay clases partial como DatosController.Cargue.cs?

Para repartir un archivo que había crecido a más de 1.400 líneas sin cambiar las URLs (un controlador nuevo cambiaría la ruta de cada acción).

¿Cómo sé qué texto va en el .resx?

Todo texto visible: títulos, botones, mensajes y errores. Se crea con la misma clave en Strings.resx (español) y Strings.en-US.resx (inglés).

¿Por qué no puedo usar onclick en el HTML?

Por la política de seguridad de contenido (CSP): solo se ejecutan los scripts con el nonce de la petición. Se usan data-* y listeners; el archivo inline-handlers.js cubre los casos simples.

¿Se pierde la sesión al publicar?

Sí: la sesión está en la memoria del servidor, así que un reinicio la cierra y los formularios abiertos dejan de ser válidos. Conviene publicar fuera de horas de uso.

¿Cómo agrego un permiso nuevo a una pantalla?

Crea la opción en la tabla MenuOpciones con su código y coloca [RequierePermiso("CODIGO")] en el controlador; luego se asigna a los usuarios desde el gestor de permisos.

¿Dónde está la documentación de seguridad?

En la biblioteca «Documentación BUFINS»: «Ciberseguridad BUFINS» y «Seguridad: blindaje del inicio de sesión».
