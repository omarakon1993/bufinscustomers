Manual de integración · API de ingesta

Cómo enviar a BUFINS, desde el sistema contable de su empresa, la misma información que hoy entra con la plantilla Excel: pasos, ejemplos, seguridad y códigos de respuesta.

1. Para qué sirve

Hoy una persona saca los números de su programa contable, los pasa a la plantilla de Excel y la sube a BUFINS. La API de ingesta permite que un programa haga ese envío solo, sin cambiar nada de lo que BUFINS ya hace con los datos: se validan con las mismas reglas, se guarda un respaldo antes de reemplazar y todo queda auditado.

Para el equipo de TI del cliente
  • Una API REST con JSON, claves por integración y un contrato OpenAPI.
  • Ejemplos listos en curl, PowerShell, Python y C#.
Para el administrador de la empresa
  • Crea y revoca las claves en Configuración → Integraciones API.
  • Decide si la integración puede confirmar o si lo hace siempre una persona.
Para el contador o analista
  • Revisa cada envío en «Revisar cargue», como con el Excel.
  • Recibe un aviso en la campana cuando hay un cargue esperando.

Importante. La API entrega los datos; los informes se actualizan al ejecutar los modelos, igual que hoy. Un envío por la API no se salta ninguna validación ni la regla de nunca dejar un año vacío.

Hay dos maneras de enviar. Ambas terminan en el mismo lugar: un cargue pendiente de revisión.

Envío A · Plantilla Excel completa

El programa del cliente (o un agente que vigila una carpeta) sube la misma plantilla de BUFINS en una sola llamada. Es lo más rápido de poner en marcha.

Recomendado para empezar
Envío B · Hojas en JSON

El programa abre un cargue, envía los datos de cada hoja como JSON (en tandas si son grandes) y lo cierra. No requiere Excel.

Para integraciones directas con el ERP

Lo que la API garantiza

  • Todo o nada. Un cargue solo cambia los datos reales cuando se confirma; antes vive aparte (staging).
  • Respaldo y deshacer. Antes de reemplazar, BUFINS guarda la versión anterior; un administrador puede deshacer desde el historial de versiones.
  • Regla de oro. Ningún cargue puede dejar un año vacío ni reducir una tabla por debajo del umbral de bloqueo; una reducción fuerte siempre la confirma una persona.
  • Un envío nuevo reemplaza al pendiente de la misma integración para la misma empresa: no se acumulan envíos sin revisar.

3. Antes de empezar: crear la integración

La clave la crea un administrador de la empresa (o de BUFINS). Se hace una sola vez por sistema que va a enviar datos.

  1. Entre a Configuración → Integraciones API y pulse Nueva integración.
  2. Elija la empresa, escriba un nombre que identifique el sistema (por ejemplo «Agente Siigo – contabilidad») y elija el usuario técnico. Se recomienda crear un usuario exclusivo («Integración API»): a su nombre quedan registradas las acciones de la API en la auditoría. No puede ser Super Admin.
  3. Opcional: escriba las IP permitidas (las direcciones desde las que el cliente enviará). Con la lista, la clave solo sirve desde ellas.
  4. Deje sin marcar «Permitir que la integración confirme cargues y ejecute los modelos» mientras se hacen las pruebas: así cada envío queda en «Revisar cargue» y lo confirma una persona.
  5. Pulse Crear. BUFINS muestra la clave una sola vez: cópiela y guárdela en el gestor de secretos del cliente. Si se pierde, se genera una nueva.

Formato de la clave: bfk_xxxxxxxx_… en producción y bft_xxxxxxxx_… en pruebas. Trátela como una contraseña: no la envíe por correo ni la guarde en el código fuente.

Entorno de pruebas (sandbox)

Antes de conectar el sistema real, el equipo del cliente puede desarrollar y probar con una integración de tipo Pruebas (campo «Tipo de integración» al crearla). Usa una clave que empieza por bft_ y funciona igual que una de producción (mismos endpoints, mismo formato, mismas validaciones, hallazgos, impacto y reglas), con estas diferencias:

  • La confirmación es una simulación. POST /cargues/{id}/confirmar (o confirmar=true) corre todas las comprobaciones, incluida la regla de nunca dejar un año vacío y la reducción fuerte, y responde ConfirmadoSimulado. No reemplaza ningún dato, no guarda respaldo y el cargue de prueba se descarta.
  • No se avisa a los revisores: un cargue de prueba no genera trabajo para nadie.
  • Duran poco y no estorban. Un cargue de prueba se descarta solo a las pocas horas y nunca impide que otra persona cargue la misma empresa y año.
  • Se nota en cada respuesta: llevan la cabecera X-Bufins-Entorno: pruebas y /ping responde "entorno": "pruebas".
  • Usuario técnico propio. No puede ser el mismo usuario de una integración de producción.

Las validaciones y el impacto se calculan contra los datos reales de la empresa, solo en lectura: así las pruebas detectan los mismos problemas que tendría el envío real. Cuando todo funcione, el administrador crea la integración de Producción y el cliente solo cambia la clave: la dirección es la misma. Si hay un cargue real pendiente de revisión para el mismo año y modo, un envío de prueba recibe 409 lote_activo: confirme o descarte ese cargue, o pruebe con otro año.

Seguimiento. En la misma pantalla, la columna Conexión muestra un semáforo en palabras simples (por ejemplo «Todo en orden», «2 cargue(s) esperan su revisión» o «El último envío quedó con errores») y el botón Ver actividad abre el detalle: última conexión, últimos envíos con su situación y un enlace a «Revisar cargue», ejecuciones de modelos y avisos al webhook. Cada administrador solo ve las integraciones de su empresa.

Asistente de conexión. El botón Asistente de conexión de esa pantalla guía a quien no es técnico según su caso: mi sistema deja un Excel en una carpeta (genera el archivo agente.json ya configurado para la integración elegida, sin la clave, permite descargar el programa AgenteBufins.exe con su huella SHA-256 para verificarlo, y explica los pasos del agente de carpeta), mi equipo de TI lo programa (da la dirección de la API, el manual, el probador y un texto listo para copiar y enviar al equipo técnico) o necesito que me ayuden (envía la solicitud al equipo de BUFINS).

Los nombres de las hojas y de las columnas que acepta cada empresa se consultan siempre con GET /api/v1/esquemas (sección 5): una hoja personalizada nueva aparece ahí sin cambios en la API.

4. Seguridad

ControlCómo funciona
Clave por integraciónCada integración tiene su propia clave, ligada a una sola empresa. BUFINS no guarda la clave: solo una huella irreversible (SHA-256) y un prefijo para ubicarla. Se muestra una única vez.
AislamientoLa empresa sale de la clave, nunca de lo que envía el cliente. Cada integración solo ve y toca sus propios cargues; si consulta uno ajeno recibe «no encontrado».
HTTPSToda llamada viaja cifrada. La clave se envía en la cabecera Authorization: Bearer, nunca en la dirección (URL).
IP permitidasOpcional por integración: fuera de esas direcciones la clave se rechaza (403).
Límites120 llamadas por minuto por integración; 20 intentos con clave incorrecta por IP en 10 minutos (luego 429 con Retry-After).
Rotar y revocarRotar genera una clave nueva y la anterior deja de servir al instante. Revocar es definitivo (se crea otra integración si hace falta).
Confirmación humanaPor defecto una persona confirma cada cargue. Aun con permiso, la API nunca confirma una reducción fuerte de datos ni salta la regla de nunca dejar un año vacío.
Webhook firmadoLos avisos salientes van firmados (HMAC-SHA256) con un secreto que se muestra una sola vez; solo se envían por https a direcciones públicas y no siguen redirecciones.
Entorno de pruebasLas claves bft_ hacen todo el flujo pero su confirmación es una simulación: nunca modifican datos reales.
AuditoríaCada envío, confirmación, descarte y cambio de la integración queda registrado con la integración y su usuario técnico. La clave nunca se registra.

Si la clave se filtra: entre a Integraciones API y use Generar clave nueva (o Revocar). El efecto es inmediato.

6. Envío A · Subir la plantilla Excel

Equivale a subir el archivo en «Cargue de Excel». El archivo debe ser la plantilla de BUFINS de su empresa, con todas sus hojas (se descarga desde esa misma pantalla).

CampoObligatorioDescripción
archivoSíLa plantilla (.xlsx o .xlsm).
anioSíAño de los datos, por ejemplo 2026. Debe ser el año de ejecución configurado o un año histórico de la empresa.
modoSíejecucion (año en curso) o historico.
idEscenarioNoEscenario de datos; por defecto 1.
confirmarNotrue pide confirmar al terminar. Solo se respeta si la integración tiene permiso y el cargue quedó limpio.

Se recomienda enviar la cabecera Idempotency-Key con un identificador único del envío (sección 11).

Agente de carpeta: envío automático sin programar

Si el sistema contable del cliente puede dejar la plantilla Excel en una carpeta (o alguien la copia allí), no hace falta programar nada: el agente de BUFINS (AgenteBufins.exe, un solo archivo, sin instalar .NET) vigila esa carpeta y sube cada archivo por esta misma API. Solo hace conexiones https salientes: no se abre ningún puerto en el servidor del cliente. BUFINS entrega el agente a quien lo solicite.

  1. Copie AgenteBufins.exe y agente.ejemplo.json a una carpeta del servidor (por ejemplo C:\BUFINS\Agente), renombre el ejemplo como agente.json y ajústelo: la carpeta que se vigila (por ejemplo C:\BUFINS\Entrada), el año, el modo y el escenario.
  2. Guarde la clave de la integración: AgenteBufins.exe --guardar-clave. Queda cifrada en clave.dat y solo la puede leer ese equipo (también se admite la variable de entorno BUFINS_CLAVE). La clave no se escribe en agente.json ni en los registros.
  3. Compruebe la conexión: AgenteBufins.exe --probar muestra la integración, la empresa y si el entorno es de pruebas o de producción.
  4. Póngalo a trabajar: como servicio de Windows (sc.exe create BufinsAgente binPath= "C:\BUFINS\Agente\AgenteBufins.exe" start= auto y luego sc.exe start BufinsAgente) o con el Programador de tareas ejecutando AgenteBufins.exe --una-vez a la hora de cada cierre.

  • Año y modo en el nombre. Un archivo llamado 2026_historico_cierre.xlsx se envía como año 2026, modo histórico; si el nombre no los trae, se usan los de agente.json.
  • No envía a medias. Ignora los temporales de Excel (~$…) y espera a que el archivo lleve 30 segundos sin modificarse y no esté abierto por otro programa.
  • Sin duplicados. Usa como Idempotency-Key la huella del contenido: copiar de nuevo el mismo archivo no crea otro cargue.
  • Modelos. Con "ejecutarModelos": true, tras un cargue confirmado pide recalcular los informes y espera el resultado (mismo permiso de confirmar).
  • Registros. Quedan en la carpeta logs\ junto al agente (30 días). Si la carpeta vigilada es de red, el servicio debe correr con una cuenta que tenga acceso a ella (la cuenta «Sistema local» no ve unidades de red). Restrinja el acceso a la carpeta del agente: quien pueda leerla puede usar su clave.

7. Envío B · Hojas en JSON

Tres pasos: abrir el cargue, enviar cada hoja y validar.

Paso 1 · Abrir el cargue

POST /api/v1/cargues
{ "anio": 2026, "modo": "ejecucion", "idEscenario": 1, "referencia": "Cierre octubre" }

Responde 201 con el idLote. referencia es un texto libre que BUFINS muestra como «archivo».

Paso 2 · Enviar cada hoja

POST /api/v1/cargues/236/hojas/Z_NombreDeLaHoja
{ "filas": [
    { "Cuenta": "110505", "Año": 2026, "Mes": 1, "Valor": 1250000.5 },
    { "Cuenta": "110510", "Año": 2026, "Mes": 1, "Valor": 980000 } ],
  "reemplazar": false }
{ "idLote": 236, "hoja": "Z_NombreDeLaHoja", "tabla": "Ini_NombreDeLaTabla",
  "filasRecibidas": 2, "filasGuardadas": 2, "filasOmitidasPorAnio": 0, "filasEnHoja": 2, "aviso": null }
  • Envíe todas las hojas de su empresa (las de /esquemas), aunque una vaya sin filas ("filas": []). Confirmar reemplaza los datos del año: una hoja olvidada borraría los suyos, por eso el cierre la exige.
  • Tandas. Una hoja grande se envía en varias llamadas (máximo 50.000 filas por llamada); las filas se van sumando. Con "reemplazar": true se descarta lo enviado antes de esa hoja y se empieza de nuevo.
  • Todo o nada. Si una fila de la llamada tiene un valor inválido, no se guarda ninguna fila de esa llamada y la respuesta indica la fila y la columna.
  • Año. Las filas cuyo año no coincide con el del cargue se omiten y se informan en filasOmitidasPorAnio (igual que el Excel).
  • Valores. Número → número JSON; texto → texto; Sí/No → true/false; fechas → texto AAAA-MM-DD; vacío → null. No se admiten objetos ni listas dentro de una fila. La columna Año también se acepta como Anio.

Paso 3 · Validar

POST /api/v1/cargues/236/validar

Verifica que se enviaron todas las hojas y corre las mismas validaciones del Excel. Responde con el estado del cargue (misma forma que el Envío A). Si falta alguna hoja: 422 hojas_faltantes con la lista. Cada vez que se agregan filas hay que volver a validar antes de poder confirmar.

Ejemplo completo en Python
import requests
BASE = "https://customers.bufins.com/api/v1"
H = {"Authorization": "Bearer bfk_..."}

lote = requests.post(f"{BASE}/cargues", headers={**H, "Idempotency-Key": "2026-10-cierre"},
                     json={"anio": 2026, "modo": "ejecucion", "referencia": "Cierre octubre"}).json()
id_lote = lote["lote"]["idLote"]

esquemas = requests.get(f"{BASE}/esquemas", headers=H).json()["hojas"]
for hoja in esquemas:
    filas = obtener_filas_del_erp(hoja["hoja"])          # su función: lista de diccionarios
    for i in range(0, max(len(filas), 1), 20000):        # tandas de 20.000
        r = requests.post(f"{BASE}/cargues/{id_lote}/hojas/{hoja['hoja']}", headers=H,
                          json={"filas": filas[i:i+20000], "reemplazar": i == 0})
        r.raise_for_status()

res = requests.post(f"{BASE}/cargues/{id_lote}/validar", headers=H).json()
print(res["lote"]["estado"], res["lote"]["totalErrores"], "errores")

8. Revisión y confirmación

Después del envío, el cargue tiene un estado. Se consulta con GET /cargues/{idLote}.

EstadoQué significaQué sigue
EnValidacionSe está llenando (Envío B) o todavía no se valida.Enviar hojas y llamar validar.
ValidadoOkSin errores ni advertencias.Revisión y confirmación.
ConAdvertenciasSe puede confirmar, pero hay avisos para revisar.Una persona decide en «Revisar cargue».
ConErroresNo se puede confirmar.Corregir los datos y volver a enviar (ver hallazgos).
ConfirmadoLos datos ya reemplazaron a los anteriores.Ejecutar los modelos para actualizar informes.
DescartadoSe canceló sin tocar datos.Enviar de nuevo si hace falta.

Hallazgos

GET /cargues/{idLote}/hallazgos?max=200 devuelve, por cada problema, la hoja, la fila, la columna, la regla, un mensaje y una sugerencia, además del total real por regla. Agregue ?idioma=en para inglés.

Impacto

GET /cargues/{idLote} incluye cuántas filas hay hoy y cuántas traería el cargue, por tabla. requiereRevisionHumana indica una reducción fuerte (la confirma siempre una persona) y bloqueado que no se puede confirmar (regla de oro).

Quién confirma

Una persona (por defecto)

El cargue queda esperando. Los administradores de la empresa reciben un aviso en la campana con el enlace a «Revisar cargue», donde pueden revisarlo y confirmarlo o descartarlo.

La integración (si se le permitió)

Con confirmar=true al subir o validar, o con POST /cargues/{id}/confirmar. Solo confirma cargues sin advertencias ni reducción fuerte; en los demás casos queda pendiente y avisa a una persona.

Actualizar los informes: ejecutar los modelos

Los informes se alimentan de los modelos. Tras confirmar un cargue, una integración con permiso puede pedir que se recalculen: POST /modelos/ejecutar. Como el cálculo puede tardar minutos, la API responde 202 enseguida con un idEjecucion y los modelos corren en segundo plano, uno tras otro; consulte el avance con GET /ejecuciones/{idEjecucion} hasta que el estado sea Completada o ConErrores.

POST /api/v1/modelos/ejecutar
{ "idEscenario": 1 }                      (el cuerpo es opcional; por defecto escenario 1)

HTTP 202
{ "idEjecucion": 41, "estado": "EnCurso", "sandbox": false, "urlEstado": "/api/v1/ejecuciones/41" }
GET /api/v1/ejecuciones/41
{ "idEjecucion": 41, "estado": "EnCurso", "idEscenario": 1, "inicio": "2026-11-14T09:00:02Z", "fin": null,
  "modelos": [ { "modelo": "PYG",     "estado": "Completado", "mensaje": "Ejecutado correctamente.", "segundos": 8.4 },
               { "modelo": "Balance", "estado": "EnCurso",    "mensaje": null,                        "segundos": null } ] }
  • Estados: EnCurso, Completada, ConErrores, Interrumpida (el sitio se reinició durante el cálculo: vuelva a ejecutarlos) y Simulada (pruebas).
  • Una a la vez. Solo puede haber una ejecución por empresa y escenario; otra llamada recibe 409 ejecucion_en_curso con el idEjecucion que está corriendo.
  • Un error no detiene a los demás. Si un modelo falla, el resto se ejecuta y el detalle por modelo trae su mensaje; los administradores de la empresa reciben un aviso.
  • Permiso. Es el mismo de confirmar cargues; sin él, 403 permiso_modelos. Una integración de pruebas no ejecuta nada (responde Simulada).

Avisos automáticos (webhook)

En lugar de consultar una y otra vez, BUFINS puede avisar a su sistema cuando algo ocurre. El administrador entra a Integraciones API, pulsa el botón Webhook de la integración y escribe la URL (https) de su sistema; BUFINS genera un secreto (se muestra una sola vez) y desde entonces envía un POST con JSON firmado a esa URL.

EventoCuándo se envía
cargue.confirmadoSe confirma un cargue de la integración: lo haya hecho la propia integración o una persona en «Revisar cargue» (lo más habitual). En pruebas llega con "simulado": true.
cargue.descartadoSe descarta un cargue de la integración (por una persona o por DELETE /cargues/{id}).
modelos.completadosTerminó una ejecución de modelos (estado Completada o ConErrores), con el detalle por modelo.
webhook.pruebaEl administrador pulsó «Enviar prueba» para verificar su receptor.

Verificar la firma

Cada aviso trae la cabecera X-Bufins-Signature: t={segundos unix},v1={firma}, donde la firma es el HMAC-SHA256 en hexadecimal de t + "." + cuerpo usando el secreto. Verifíquela siempre antes de confiar en el aviso, con el cuerpo exacto recibido (sin reformatear), y rechace los que tengan más de 5 minutos.

Python
import hmac, hashlib, time

def verificar(secreto: str, cuerpo: bytes, cabecera: str) -> bool:
    p = dict(x.split("=", 1) for x in cabecera.split(","))        # "t=...,v1=..."
    if abs(time.time() - int(p["t"])) > 300:                       # rechaza avisos viejos (anti-repetición)
        return False
    esperado = hmac.new(secreto.encode(), p["t"].encode() + b"." + cuerpo, hashlib.sha256).hexdigest()
    return hmac.compare_digest(esperado, p["v1"])
C#
static bool Verificar(string secreto, string cuerpo, string cabecera)
{
    var p = cabecera.Split(',').Select(x => x.Split('=', 2)).ToDictionary(x => x[0], x => x[1]);
    if (Math.Abs(DateTimeOffset.UtcNow.ToUnixTimeSeconds() - long.Parse(p["t"])) > 300) return false;
    var esperado = Convert.ToHexString(HMACSHA256.HashData(
        Encoding.UTF8.GetBytes(secreto), Encoding.UTF8.GetBytes(p["t"] + "." + cuerpo))).ToLowerInvariant();
    return CryptographicOperations.FixedTimeEquals(Encoding.ASCII.GetBytes(esperado), Encoding.ASCII.GetBytes(p["v1"]));
}
  • Responda con un 2xx en menos de 15 segundos y procese después. Cualquier otra respuesta se considera fallida.
  • Reintentos: hasta 3 intentos (inmediato, a los 30 segundos y a los 5 minutos). Si todos fallan queda como Fallido en la pantalla de la integración; los pendientes se retoman con la siguiente actividad de la API.
  • Puede llegar repetido. Use X-Bufins-Delivery (o el campo id) para ignorar avisos que ya procesó.
  • Destino seguro. Solo https y direcciones públicas de internet: BUFINS no envía a redes internas, ni sigue redirecciones.
  • Secreto perdido: «Generar secreto nuevo» invalida el anterior al instante; actualice su sistema.

En el entorno de pruebas la confirmación se simula: la respuesta trae "estado": "ConfirmadoSimulado" (o "confirmacion": "simulado" al subir con confirmar=true) y el cargue de prueba se descarta sin tocar datos.

Antes de reemplazar, BUFINS guarda automáticamente la versión anterior. Si un cargue confirmado resulta incorrecto, un administrador puede deshacerlo desde el Historial de versiones.

11. Buenas prácticas

Repetir sin duplicar

Envíe Idempotency-Key en POST /cargues y /cargues/archivo, con un valor único por envío lógico (por ejemplo «empresa-año-mes-consecutivo»). Si la llamada se repite por una falla de red, BUFINS devuelve el cargue ya creado ("repetido": true) en vez de crear otro. La clave se recuerda 7 días.

Frecuencia

Basta un envío diario, semanal o mensual: la información es financiera, no transaccional. Cada envío trae el año completo a la fecha y reemplaza el anterior; repetirlo no duplica datos.

Reintentos

Ante 429 o 5xx espere y reintente con la misma Idempotency-Key. Ante 4xx corrija primero: reintentar sin cambios no lo arreglará.

Vigencia de un cargue

Un cargue esperando revisión se conserva 48 horas; uno que se está llenando por hojas, 6 horas. Pasado ese tiempo se descarta y hay que enviarlo de nuevo.

Tamaño

La plantilla puede pesar hasta 100 MB. En el Envío B use tandas de 20.000 filas o menos por llamada (el máximo es 50.000).

Pruebas

Desarrolle primero con una integración de Pruebas (clave bft_): hace todo el flujo sin tocar datos reales. Ya en producción, empiece con la confirmación humana activa y compare los resultados con los del Excel durante algunos cierres antes de pedir que la integración confirme sola.

12. Preguntas frecuentes

¿Tengo que dejar de usar el Excel?

No. El Excel sigue funcionando siempre, por la misma puerta y con las mismas validaciones. La API es una alternativa; puede alternarlas.

¿Qué pasa si envío dos veces lo mismo?

Con la misma Idempotency-Key BUFINS no lo duplica. Sin ella, el segundo envío reemplaza al primero si aún estaba pendiente; si el primero ya se confirmó, el segundo se revisa y reemplaza los datos del año, como un cargue nuevo de Excel.

¿Por qué el cargue «no se puede confirmar»?

Consulte /cargues/{id}/hallazgos. Si tiene errores hay que corregir los datos; si el impacto muestra bloqueado, el archivo dejaría un año vacío o una tabla casi vacía y BUFINS lo impide para todos.

¿La API actualiza los informes?

Un cargue confirmado deja los datos listos; los informes leen los resultados de los modelos. Una integración con permiso los recalcula con POST /modelos/ejecutar; si no, se ejecutan en «Ejecución de Modelos», como siempre.

¿Cómo me entero cuando una persona confirma el cargue?

Configure un webhook: BUFINS le envía cargue.confirmado en cuanto alguien lo confirma en «Revisar cargue». Si no puede recibir avisos, consulte GET /cargues/{id} cada cierto tiempo.

¿Puedo ver los cargues de otra integración o de las personas de la empresa?

No. Cada integración ve únicamente los cargues que ella misma creó. Las personas los ven en «Revisar cargue».

Perdí la clave, ¿qué hago?

Un administrador entra a Integraciones API y pulsa «Generar clave nueva». La anterior deja de funcionar al instante; configure la nueva en el sistema del cliente.

¿Mis datos están protegidos?

Viajan cifrados (HTTPS), cada clave solo alcanza una empresa y todo lo que hace la integración queda en la auditoría. BUFINS actúa como encargado del tratamiento de los datos de la empresa; el contrato de transmisión de datos se acuerda por separado.
