Connect your system to BUFINS

Send your accounting data to BUFINS from your own system, without uploading Excel by hand. This guide covers the essentials, step by step.

What it is

Each company has its own API: an address and an access key. Your system sends data to that address using the key, and BUFINS receives it with the usual checks: it is validated, a backup is saved before anything is replaced, and everything is logged. A person at your company reviews and confirms each upload, unless automatic confirmation is allowed.

If you manage the company

Create the connection in Settings → API connections → Connect a company. You will get the address and the key to hand to your technical team.

If you are on the technical team

You need the address and key given by the administrator. With those you can already send data; follow the three steps below.

Start in 3 steps

  1. Get the address and the key. The address looks like this: https://customers.bufins.com/api/v1/your-company. The key starts with bfk_ (live data) or bft_ (testing only). Keep it like a password: it is shown only once.
  2. Check the connection. It should answer “ok” and your company name.
    curl -H "Authorization: Bearer YOUR_KEY" https://customers.bufins.com/api/v1/your-company/ping
  3. Send the data template. It is the same BUFINS Excel file (year, type and file).
    curl -X POST https://customers.bufins.com/api/v1/your-company/cargues/archivo \
  -H "Authorization: Bearer YOUR_KEY" \
  -F "archivo=@template.xlsx" -F "anio=2026" -F "modo=ejecucion"

Recommended. Start with a Just testing connection (bft_ key): it goes through the whole flow without changing any real data. When it works, the administrator creates the live-data connection and you only swap the key.

No coding. You can try each call in the Interactive tester (/api/v1/docs) by pasting your key: no code needed.

Each upload returns a number (idLote). Use it to check its status. If the upload ends with errors, the findings are shown so you can fix them and send again; the new upload replaces the pending one.

Who confirms. By default a person confirms in “Review upload” and gets a bell notification. The API never confirms on its own an upload that would leave a year empty or sharply shrink a table.

If something fails

Every error response carries a code and a message in Spanish (or English with ?idioma=en).

CodeWhat it meansWhat to do
401 no_autorizadoThe key is missing, wrong or cancelled.Check the key; ask the administrator for a new one.
403 ip_no_permitidaThat key can only be used from certain IP addresses.Use the authorized server or ask to extend the list.
404 direccion_no_correspondeThe address belongs to another company.Use the address given in the message.

409 lote_activoA live upload is already waiting for review for that year and type.Have a person confirm or discard it.
422 solicitud_invalidaA value is missing or the file is not valid.Read the message: it says what to fix.
429Too many calls (limit: 120 per minute) or too many attempts with a wrong key.Wait a moment and retry.

Security

  • A key opens only its own company. It cannot see or touch another company's data, even if it knows an upload number.
  • The key is shown only once and BUFINS does not store it in clear. If it is lost or leaked, the administrator generates a new one and the old one stops working instantly.
  • Store it in your company's secrets system; never in code or open emails.
  • The administrator can restrict the key to certain IP addresses and cancel the connection at any time.
  • Everything is audited: who sent what, when, and the result.

Advanced

Send by sheets instead of an Excel file

For systems that cannot produce the file: open the upload with POST /cargues ({"anio":2026,"modo":"ejecucion"}), send each sheet with POST /cargues/{idLote}/hojas/{hoja} ({"filas":[{"Column":value}]}) and close it with POST /cargues/{idLote}/validar. You must declare all of the company's sheets (with "filas":[] if there is no data); the exact names come from GET /esquemas. The result is identical to the Excel. Two important points: each upload must carry the whole year of every sheet (not just what is new), because confirming it replaces what was there; and the chart-of-accounts (PUC) sheet is not sent by JSON: it is loaded once with the Excel.

Automatic notices (so your system finds out by itself)

The administrator can register an https address of your system under More options → Automatic notices. BUFINS will notify it when an upload is confirmed, discarded or the models finish. Each notice carries the X-Bufins-Signature header (HMAC-SHA256 signature of the text time.body with the secret shown when they are enabled) so you can verify it comes from BUFINS. If your system does not answer, it is retried 3 times. Not needed to get started: you can also check the status whenever you like.

Avoid duplicate uploads

If you add the Idempotency-Key header (a unique text per upload), resending the same file after a network cut does not duplicate the upload: BUFINS returns the original one with "repetido": true.

Technical contract and tools

The full contract is at /api/v1/openapi.json (importable in Postman). The interactive tester is at /api/v1/docs.

FAQ

Why does the address include my company name?

So it is obvious whose connection it is and to prevent mix-ups: if you use one company's key with another company's address, BUFINS answers with the right address.

Do reports update when I send data?

The upload delivers and validates the data; once confirmed it is loaded. Reports update when the models run, as today (this can also be requested through the API).

Can I keep using Excel?

Yes. The API and manual upload coexist and use exactly the same rules.

Where do I see what my system has sent?

In API connections → View uploads: each upload with its date, result and, if it is waiting for review, a direct link to review it.
