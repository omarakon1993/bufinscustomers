1. System overview

BUFINS is a web platform for financial management and analysis for companies and business groups: it receives accounting data in Excel, validates it, runs calculation models and presents it in management reports supported by artificial intelligence. This document gathers its technical specifications, current versions, what it contains, its features and its cybersecurity controls, so it can be consulted for any technical question.

3. Architecture

A layered, single-solution application with no external services of its own: the browser talks to the application and the application to SQL Server; the only outbound calls are email and the AI API.

LayerWhat it contains
ControllersReceive the request, validate access and call services. All inherit from BaseController (messages, text translation, AI access validation).
ServicesBusiness logic and SQL Server access; inherit from BaseService (connection string).
ModelsData and view models.
ViewsRazor views organized by functional area (Settings, Data, Reports…), with layout, shared partials and a dynamic menu.
Helpers / Filters / PermisosHelpers (session, companies, theme, Excel, email…), global filters and authorization attributes (ValidarSesion, RequierePermiso, SoloSuperAdmin).
Compat / InfraCompatibility layer that keeps the previous site’s way of working (session, configuration, cache) and the startup infrastructure (CSS/JS bundles, security headers, paths).

Cross-cutting pieces

  • Session: in server memory, 20 minutes of inactivity (sliding), cookie BUFINS_SessionId; an on-screen warning at 5 minutes and a silent renewal while the user is active.
  • Configuration: appsettings.json (non-secret values) and secretsSettings.json (connection string and keys; outside the repository and the package). Business parameters in the ConfiguracionSistema table, editable on screen.
  • Logging: one file per day in App_Data/logs with 30-day retention, including IP, user, URL and the full exception chain.
  • Errors: branded error pages (403, 404, 500) independent of the session; only controlled messages with a reference code reach the browser, never the technical detail.
  • Cache: in memory with short expiry (companies, scenarios, upload sheets, permissions) invalidated on save.
  • Texts: every visible text lives in Spanish and English resource files; no screen carries hard-coded text.

Data rules

  • Scenarios: each company can have several parallel copies of its data (Scenario 1 is the main one); the company configuration is shared.
  • Reports and AI read only from the Modelo* tables, never from the upload tables. Reports do not run models: they show what the last model left.
  • A year is never left empty: uploads, restores and recoveries share a rule that blocks the operation if it would leave a table almost empty.
  • T-SQL compatible with SQL Server 2012: no STRING_AGG, TRIM, JSON functions or CREATE OR ALTER.

Roles

6. Cybersecurity

Summary of the controls in place, organized by topic. The findings detail and the roadmap are in the “Official cybersecurity documentation” of the library.

TopicControl
PasswordsHashing with BCrypt (cost 12) and transparent migration of old formats. Policy: minimum 12 characters, complexity, no repetitions or common passwords, not containing the username, and a check against leaked passwords (Have I Been Pwned by range, without sending the password). When creating a user, a change at first login can be required.
LoginEqual response time for a nonexistent user and a wrong password (no enumeration by timing). Per-IP attempt limit with a temporary block and a defensive mode when there is a general spike of failures; real-account lockouts notify the Super Admins.
Two-factorOne-time code (TOTP, RFC 6238) with an authenticator app, required at every login; protection against code reuse and discard after 5 wrong attempts. The secret is stored encrypted. No recovery codes on purpose: if a user loses their methods, a Super Admin resets them after verifying identity through another channel.
Passkeys (WebAuthn)Optional additional method, with its own verification of the signature, origin and challenge; requires user verification. Registering or removing one requires reconfirming with the app code and sends a notification and an email.
RecoveryReset request only after validating the password, approved by a Super Admin (nobody approves their own) with the evidence of the request; everything is audited and the user is notified by email.
Session and cookies20-minute inactivity session with automatic sign-out; session cookie with HttpOnly, SameSite=Lax and Secure (over HTTPS); antiforgery protection on the actions that change data.
HeadersStrict-Transport-Security (1 year, subdomains), X-Content-Type-Options: nosniff, X-Frame-Options: SAMEORIGIN, Referrer-Policy, Permissions-Policy (camera, microphone and location disabled), Cross-Origin-Opener-Policy and an enforced Content-Security-Policy plus a stricter one in report-only mode, whose reports are logged. No headers that reveal the server.
Data and filesAll data access uses parameters (user text is never concatenated). Uploaded files are validated by their actual content (byte signature), not by extension; logos are redrawn and stripped of metadata; 100 MB limit per upload.
Isolation between companiesEvery company-scoped query goes through a single access rule (own plus those of its group). Upload batches are isolated by identifier and a lock prevents two simultaneous uploads of the same company, year, mode and scenario.
Secret encryptionAI keys and two-factor secrets are stored encrypted with the application’s machine keys. The connection string and keys live outside the repository and the published package.
AuditCentral change log (who, when, from which IP, previous and new value), security events, navigation by user (90-day retention), uploads, email sending and documentation views. The log never interrupts the operation.
Artificial intelligenceAI only receives already-calculated figures from the model tables (no detailed data or other tables); access, functions and budget are controlled per company and every query is measured and audited.
DocumentationServed from a non-public folder, requires a session, carries a watermark with who is viewing it, is not cached, refuses to open directly in a tab and every view is audited. The Super Admin decides which documents are Super Admin only.
Backup and recoveryA snapshot before each upload and recoverable versions (the two most recent per company, year, mode and scenario), an automatic backup before restoring, and full site backups before each deployment.

Known points and recommendations

  • CSP policy: the enforced policy still allows inline scripts; the stricter one runs in report-only mode. Enforcing it requires moving inline scripts to files.
  • Interface libraries: Bootstrap 4.6 and jQuery 3.6 are older than the current versions (see section 2).
  • In-memory session: restarting the site or deploying closes all sessions; the design is single-server.
  • Data-protection keys: on the current hosting the site identity cannot create files in its folder, so they live in memory (a restart invalidates open forms). Permission was requested from the provider.
  • Deployment: the provider’s Web Deploy certificate is self-signed and is explicitly accepted in the publish profile.
  • Credentials: rotate the SQL password periodically and update it in the server’s secretsSettings.json (the change requires restarting the site).
  • Testing: there are no automated tests; verification is done by comparing screens and responses against the previous system and with real sessions.

7. Operations and deployment

How it is published

StepWhat is done
1Build the self-contained package (dotnet publish, Release, win-x64).
2Back up the whole current site with the deployment script (local copy through Web Deploy).
3If the keys or connection string changed: upload secretsSettings.json and restart the site.
4Simulate the deployment (shows what it would create, change and delete, without touching anything) and review it.
5Deploy: the site shows a maintenance page for a few minutes while the files are copied; secrets, keys, logs and panel files are not touched.
6Smoke tests with a real session (login with two-factor, the menu and several reports). If something fails: restore the backup.

Maintenance

  • SQL scripts: structure changes are delivered as numbered scripts run by the owner in SQL Server; once applied they are removed from the repository.
  • Automatic cleanup: unconfirmed upload batches are discarded on their own (on leaving, on sign-out and by expiry); notifications older than 30 days and navigation older than 90 days are purged opportunistically, with no scheduled jobs.
  • Adding a report: service + controller + view, option in the menu manager, text in both languages, standard export, palette, logo, documentation capsule and an entry in the documentation catalog.
  • Documentation: documents are generated with the scripts in Tools/Documentacion; Spanish and English are maintained together.

8. Frequently asked questions

Which .NET version does it use and until when is it supported?

.NET 10, a long-term support (LTS) release. Support is defined by Microsoft; it is worth checking when planning the next update.

Where is it hosted?

On a shared Conexcol hosting (Windows/IIS with Plesk), with access to SQL Server. It is deployed through Web Deploy.

How is one company’s data protected from another’s?

Every query goes through a company and group access rule; only the Super Admin sees all. See “Isolation between companies”.

What happens if the second-factor phone is lost?

The user requests a reset from the verification screen; a Super Admin approves it after verifying identity through another channel.

What data does the artificial intelligence receive?

Only already-calculated figures from the model tables of the queried company; never detailed upload data.

How do you roll back if a deployment fails?

With the full backup made before deploying, restored with the same script.

Who can see this document?

By default only the Super Admin. In the “BUFINS Documentation” library each document is marked or unmarked as “Super Admin only”.
