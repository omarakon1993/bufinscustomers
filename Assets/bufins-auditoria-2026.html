A — Vulnerabilidades de Seguridad
A1
✅ IMPLEMENTADO CSRF — Falta [ValidateAntiForgeryToken] en la mayoría de controladores
Solo 9 ocurrencias en 4 de 29 controladores · Login y Registro sin protección
🔴 Crítico ▼
Un atacante puede crear una página web maliciosa que envíe formularios HTTP POST en nombre de un usuario autenticado sin que este lo sepa. Los endpoints más críticos sin protección son los de Login y Registro (AccesoController.cs:32 y AccesoController.cs:78).
Riesgo concretoUn atacante puede forzar el registro de cuentas, cambiar configuraciones de empresa, eliminar reportes o ejecutar modelos financieros desde la sesión de un usuario sin su consentimiento.
// ❌ Actual — sin protección [HttpPost] public ActionResult Login(Usuarios oUsuario) { ... } // ✅ Correcto [HttpPost] [ValidateAntiForgeryToken] public ActionResult Login(Usuarios oUsuario) { ... }
// ✅ En CADA formulario de vista .cshtml @using (Html.BeginForm()) { @Html.AntiForgeryToken() ... }
CorrecciónAgregar [ValidateAntiForgeryToken] a todos los métodos POST en los 29 controladores. Agregar @Html.AntiForgeryToken() en todos los formularios de vistas. Esfuerzo: 2–4 horas.
⏱ 3–4 h 🎯 Prioridad #1 📂 Todos los controladores
A2
Modo Debug activo en producción (debug="true")
Web.config:23
🔴 Crítico ▼
<compilation debug="true"/> en Web.config expone stack traces completos, nombres de variables internas y rutas del servidor en mensajes de error visibles al usuario. Además reduce el rendimiento (~30% más lento en compilación JIT).
// ❌ Web.config actual (línea 23) <compilation debug="true" targetFramework="4.8"/> // ✅ Correcto para producción <compilation debug="false" targetFramework="4.8"/>
CorrecciónCambiar a debug="false" y usar Web.Release.config transform para asegurar que nunca se despliegue en debug. Esfuerzo: 5 minutos.
⏱ 5 min 🎯 Prioridad #2
A3
✅ IMPLEMENTADO Endpoints de debug públicos exponen datos de sesión
AccesoController.cs:288 — InfoSesion() · AccesoController.cs:326 — DebugUsuario()
🟠 Alto ▼
Los métodos InfoSesion() y DebugUsuario() retornan JSON con nivel de admin, IdEmpresa, ID de usuario y claves de sesión a cualquier usuario autenticado que navegue a la URL directamente. Cualquier usuario normal puede ver la estructura de permisos del sistema.
CorrecciónEliminar ambos métodos si no están en uso activo. Si se necesitan para diagnóstico, envolverlos en #if DEBUG o restringirlos a Super Admin y registrar cada acceso en auditoría.
⏱ 15 min 🎯 Prioridad #3
A4
✅ IMPLEMENTADO HealthController filtra mensajes de excepción de base de datos
HealthController.cs:28 — dbError = ex.Message
🟡 Medio ▼
El endpoint GET /Health no requiere autenticación (no tiene [ValidarSesion]) y expone el mensaje de excepción SQL completo cuando hay error de conexión. Esto puede revelar el nombre del servidor SQL, cadena de conexión parcial y versión del motor de base de datos.
// ❌ Actual catch (Exception ex) { dbStatus = "error"; dbError = ex.Message; // expone: "Cannot open server X login failed for user Y" } // ✅ Correcto catch (Exception ex) { dbStatus = "error"; Log.Error(ex, "Health check DB failure"); // dbError omitido en respuesta JSON }
⏱ 10 min 🎯 Prioridad #4
A5
✅ IMPLEMENTADO Falta cabecera Content-Security-Policy (CSP)
Web.config:83-94 — Cabeceras parciales
🟡 Medio ▼
El sitio tiene X-Content-Type-Options, X-Frame-Options, HSTS y Referrer-Policy, pero falta Content-Security-Policy y X-XSS-Protection. Sin CSP, un XSS inyectado puede ejecutar scripts arbitrarios.
<add name="Content-Security-Policy" value="default-src 'self'; script-src 'self' 'unsafe-inline' cdnjs.cloudflare.com; style-src 'self' 'unsafe-inline' cdnjs.cloudflare.com fonts.googleapis.com; font-src 'self' fonts.gstatic.com cdnjs.cloudflare.com; img-src 'self' data:; connect-src 'self'"/> <add name="X-XSS-Protection" value="1; mode=block"/>
⏱ 1–2 h 📂 Web.config
A6
✅ IMPLEMENTADO Fijación de sesión — SessionID no se regenera al hacer login
UsuarioSesionHelper.cs — EstablecerUsuarioEnSesion()
🟡 Medio ▼
Aunque regenerateExpiredSessionId="true" está configurado (regenera sesiones expiradas), el ID de sesión no se abandona y regenera en el momento exacto del login. Un atacante que capture el SessionID de una sesión no-autenticada puede usarlo para asumir la identidad del usuario después del login.
// ✅ Agregar ANTES de EstablecerUsuarioEnSesion var oldItems = Session.Keys.Cast<string>() .ToDictionary(k => k, k => Session[k]); Session.Abandon(); Session.Clear(); // El nuevo request genera un nuevo SessionID automáticamente foreach (var item in oldItems) Session[item.Key] = item.Value;
⏱ 1 h 📂 UsuarioSesionHelper.cs
A7
✅ IMPLEMENTADO Sin límite de velocidad por IP en login y registro
AccesoController.cs — Brute-force por cuenta protegido, no por IP
🟡 Medio ▼
El sistema ya tiene protección de bloqueo de cuenta por intentos fallidos (columnas IntentosFallidos y BloqueadoHasta), pero un atacante puede hacer fuerza bruta distribuida con múltiples cuentas desde la misma IP sin ser detectado, o enumerar usuarios a través del mensaje de respuesta.
Corrección sugeridaImplementar throttling por IP usando un cache en memoria (diccionario + timestamp). Alternativamente, integrar un CAPTCHA de Google reCAPTCHA v3 en el formulario de login después del 3er intento fallido desde la misma IP.
⏱ 3–5 h 📂 AccesoController.cs + BaseController.cs
A8
✅ IMPLEMENTADO Uso inconsistente de Html.Raw() en vistas — riesgo XSS
Varios archivos .cshtml — inyección de strings de recursos vía JS
🟡 Medio ▼
Se usa @Html.Raw(Resources.Strings.Key) para inyectar strings en variables JavaScript dentro de los scripts de las vistas. Si un valor de recurso contiene caracteres especiales (', <, >, "), puede romper el contexto JavaScript y abrir un vector XSS.
// ❌ Actual — inseguro var msg = '@Html.Raw(Resources.Strings.Login_ErrorEmail)'; // ✅ Correcto — codificar para contexto JS var msg = '@HttpUtility.JavaScriptStringEncode(Resources.Strings.Login_ErrorEmail)';
⏱ 2 h 📂 Todas las vistas con bloques <script>
A9
Timeout de comandos SQL no configurado en servicios
Todos los servicios con SqlCommand — por defecto 30 segundos del pool
🟢 Bajo ▼
Ningún SqlCommand en los servicios tiene CommandTimeout explícito. El timeout por defecto del pool de conexiones de .NET es 30 segundos, pero queries pesadas (como las de modelos de ejecución) pueden demorar más, consumiendo conexiones del pool y degradando el servicio para otros usuarios.
// ✅ Agregar en todos los SqlCommand de servicios var cmd = new SqlCommand("sp_ObtenerDatos", cn); cmd.CommandTimeout = 30; // queries normales // Para ModelosEjecucion ya está en 300s — correcto
⏱ 1 h 📂 BaseService.cs o cada servicio
A10
✅ IMPLEMENTADO Migración SHA256→BCrypt sin validación del UPDATE
AccesoController.cs:140–153
🟢 Bajo ▼
Al detectar un hash SHA256, el código actualiza la contraseña del usuario al formato BCrypt pero no verifica si el ExecuteNonQuery() afectó exactamente 1 fila. Si el UPDATE falla silenciosamente por un error de concurrencia, el usuario queda con hash vacío o corrupto.
int rows = cmd.ExecuteNonQuery(); if (rows != 1) throw new Exception("Error al migrar contraseña: filas afectadas = " + rows);
⏱ 30 min 📂 AccesoController.cs

B — Rendimiento y Escalabilidad
B1
Sin paginación en ningún listado — carga total en memoria
UsuarioController · EmpresaController · ReportesController · AuditoriaCarguesController
🟠 Alto ▼
Todos los listados cargan el 100% de los registros en memoria y los envían al cliente. Con crecimiento en datos (10.000+ registros de auditoría, histórico de cargues, usuarios multi-empresa), esto producirá picos de memoria y tiempos de respuesta inaceptables.
// ✅ Patrón a implementar en stored procedures SELECT * FROM Usuarios WHERE IdEmpresa = @IdEmpresa ORDER BY Nombre OFFSET (@Pagina - 1) * @TamanoPagina ROWS FETCH NEXT @TamanoPagina ROWS ONLY;
⏱ 1–2 días 🎯 Alto impacto 📂 4+ controladores · 4+ SPs
B2
Logs de importación Excel almacenados solo en Session (volátiles)
DatosController.cs — Session["LogImportacion"]
🟡 Medio ▼
El log completo de importación se almacena en Session. Si la sesión expira antes de que el usuario descargue el log, se pierde para siempre. Además, logs de importaciones grandes (miles de filas) consumen memoria de IIS sin límite.
Mejora sugeridaPersistir los logs en la tabla AuditoriaImportacion (a crear) con columnas: Id, UsuarioId, NombreArchivo, FilasOk, FilasError, FechaHora, TextoLog. Permitir consultar el historial desde Auditoría de Cargues.
⏱ 4–6 h 📂 DatosController.cs + nueva tabla
B3
⚠️ REVERTIDO Caché de permisos y menú sidebar por idioma — cache miss al cambiar idioma
UsuarioSesionHelper.cs — Claves con sufijo de cultura
🟡 Medio ▼
La clave de caché del menú sidebar incluye el código de cultura (UsuarioMenuSidebar_es-CO). Cada vez que el usuario cambia de idioma se invalida el caché y se ejecuta una nueva consulta a BD. Dado que el menú solo contiene nombres en un idioma, este sufijo es innecesario.
CorrecciónUsar clave fija "UsuarioMenuSidebar". Si en el futuro se requieren menús multilingues, manejar la traducción en la vista, no en el caché.
⏱ 30 min 📂 UsuarioSesionHelper.cs
B4
Sin manejo de errores centralizado — excepciones no logeadas
App_Start/FilterConfig.cs — Sin GlobalExceptionFilter
🟡 Medio ▼
No existe un filtro de excepción global registrado en FilterConfig. Las excepciones no capturadas en controladores muestran páginas de error genéricas pero no se loguean en ningún sistema centralizado. Cuando algo falla en producción, no hay visibilidad.
// App_Start/FilterConfig.cs filters.Add(new HandleErrorAttribute()); filters.Add(new GlobalExceptionFilter()); // ← agregar
⏱ 2 h 📂 FilterConfig.cs + nuevo GlobalExceptionFilter
B5
Sin framework de logging estructurado (Serilog / NLog)
Codebase — Solo logging ad-hoc en DatosController
🟡 Medio ▼
No existe un sistema centralizado de logging. El único log disponible es el de importación de Excel en DatosController, que es temporal en sesión. Operaciones críticas como creación de usuarios, cambios de permisos y ejecución de modelos no dejan rastro.
RecomendaciónInstalar Serilog via NuGet (Serilog.AspNet). Configurar sink a archivo rotativo y opcionalmente a Application Insights o Seq. Agregar logs en: login/logout, creación/eliminación de entidades, errores de importación, consultas IA.
⏱ 4 h setup + gradual 📂 Global.asax.cs + BaseController.cs

C — Funcionalidades Nuevas Sugeridas
C1
Tabla de Auditoría de Acciones Críticas
Trazabilidad completa: quién hizo qué, cuándo y desde qué IP
🟣 Feature ▼
Crear una tabla AuditoriaSistema que registre automáticamente todas las operaciones sensibles: creación/eliminación de usuarios, cambios de permisos, login/logout, ejecuciones de modelos, rollbacks de versiones.
-- Nueva tabla CREATE TABLE AuditoriaSistema ( Id INT IDENTITY PRIMARY KEY, IdUsuario INT, Accion VARCHAR(100), -- 'LOGIN', 'CREAR_USUARIO', etc. Descripcion NVARCHAR(500), IdEmpresa INT, IPAddress VARCHAR(45), UserAgent VARCHAR(300), FechaHora DATETIME2 DEFAULT GETUTCDATE() );
⏱ 1 día 💡 Impacto: Compliance + Seguridad
C2
Restablecimiento de contraseña por correo electrónico
Actualmente el admin debe cambiar la clave manualmente — UsuarioController
🟣 Feature ▼
Agregar flujo de auto-reset de contraseña: el usuario ingresa su correo, el sistema envía un enlace con token de un solo uso (TTL 1 hora), el usuario establece nueva contraseña. Reduce carga al admin y mejora experiencia de usuario.
-- Columnas a agregar en Usuarios ResetToken VARCHAR(128) NULL, ResetTokenExp DATETIME NULL // Flujo: SolicitarReset() → enviar email → ValidarToken() → CambiarClave()
⏱ 1–2 días 📦 NuGet: SmtpClient o SendGrid 💡 UX crítico
C3
Autenticación en dos factores (2FA) con TOTP
Google Authenticator / Microsoft Authenticator
🟣 Feature ▼
Agregar opción de 2FA opcional por usuario usando TOTP (RFC 6238). Al activar, el usuario escanea un QR con Google/Microsoft Authenticator. En cada login se solicita el código de 6 dígitos. Especialmente importante para Super Admin y Admin de Empresa.
-- Columnas a agregar en Usuarios Totp2FASecret VARCHAR(32) NULL, Totp2FAActivo BIT DEFAULT 0 // NuGet: Otp.NET para generar/validar códigos TOTP
⏱ 2–3 días 📦 NuGet: Otp.NET + QRCoder 💡 Seguridad admin
C4
Sesiones activas: ver y cerrar sesiones concurrentes
Detectar acceso simultáneo desde múltiples dispositivos
🟣 Feature ▼
Crear tabla SesionesActivas que registre logins activos con IP, User-Agent y timestamp. Los admins pueden ver qué usuarios están conectados, desde dónde, y cerrar sesiones remotamente. Los usuarios pueden ver sus propias sesiones activas en su perfil.
CREATE TABLE SesionesActivas ( SessionId VARCHAR(128) PRIMARY KEY, IdUsuario INT, IPAddress VARCHAR(45), UserAgent VARCHAR(300), Inicio DATETIME2, UltimaAct DATETIME2 );
⏱ 1 día 💡 Seguridad + UX
C5
Dashboard de métricas del sistema para Super Admin
Uso de IA, cargues por empresa, usuarios activos, errores recientes
🟣 Feature ▼
Pantalla dedicada para Super Admin con tarjetas de KPIs del sistema: consultas IA en las últimas 24h, cargues Excel exitosos vs. fallidos, empresas con actividad reciente, usuarios activos hoy, errores en los últimos 7 días. Datos provenientes de las tablas de auditoría existentes.
⏱ 2–3 días 📦 Chart.js (ya en proyecto) 💡 Visibilidad operativa
C6
Historial persistente de logs de importación Excel
Reemplaza Session["LogImportacion"] por tabla en BD
🟣 Feature ▼
Persistir los logs de cada cargue en una tabla LogsImportacion. Permite al usuario volver al módulo de auditoría días después y re-descargar el log de cualquier cargue previo. También habilita análisis de patrones de error.
⏱ 4–6 h 💡 Reemplaza lógica existente
C7
Feature Flags — activar/desactivar funciones sin redeploy
Tabla FeatureFlags en BD + helper en sesión
🟣 Feature ▼
Tabla FeatureFlags con Codigo, Activo (bit), Descripcion. En Super Admin, una pantalla permite activar/desactivar funcionalidades en vivo (sin redeploy). Útil para rollout gradual de nuevas features o rollback de emergencia.
// Uso en controlador if (FeatureFlagHelper.EstaActivo("NUEVA_FUNCION_2FA")) return View("~/Views/Seguridad/Configurar2FA.cshtml");

C8
Exportación avanzada: PDF + Excel con formato desde Informes IA
Descarga directa del análisis IA como documento formateado
🟣 Feature ▼
Agregar botón "Descargar PDF" en el módulo de Análisis IA que genere un documento con: encabezado de empresa, tabla de datos consultada, y la respuesta del análisis formateada en markdown. Usar DinkToPdf o iTextSharp para generar PDF desde el HTML renderizado.
